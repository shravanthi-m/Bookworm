1 · Home & level not run

arm: ?
Goes home, then reads the table's tilt in the depth image. The tilt is removed from depth in software.

2 · First capture not run

One photo from home; the book's outline gives six points: four corners and the centre of each page.

3 · Depth scan not run

The camera visits spots around the book's midpoint (from the first capture) at home height (never lower) and fuses the depth views into the page's height above the table.

4 · Z link not run

table z in the arm frame
-
Lowers the tip in 2 mm steps onto bare table at least 80 mm from the book, reading the joint load after every step. The spot is the bare table farthest from the book, out at the edge of what the camera sees (it is locked after the first touch). When the load jumps the arm goes straight back one step (and home, if the load stays high); that height is the table's z. Then up, across, and the same on the left-page centre (CL) as a check. Charts: real tip z per step against the fitted trend; below, how far each step is off the trend for position and load. Every run is saved in data/depth/zlink/.

5 · Book model not run

model file
No motion. The book's height in the arm frame, driven by where the tip has really touched the page (the Z link's BL touch, plus any touch that met the page early): one touch or two give one level for the whole book, three or more spread out give a tilted plane. The depth map is only a reference (the book outline, and a "depth is off by" column); it never moves the model. The demo touches at this height plus your units, and any early contact is merged back in afterwards (v2, v3, ...). Saved in data/book/: book_model.json + book_model.npz (the grid).

6 · Touch calibration (XY + Z) not run

XY correction in use
-
Only for the XY correction. Not part of Run all; no depth map needed. 1) Needs the Z link (done after the first capture): it measured the book height at CL. 2) For each ticked point (BL first) the arm goes straight over it and comes down in 2 mm steps to that book height plus the chosen units above (the light touch: no pressure, so the XY is not disturbed). If the load jumps earlier the page is higher there; that is reported. 3) It holds the light touch for a second, then goes on to the next point. Nothing to press while it moves. 4) After the last point the arm goes home and the viewer switches to "XY marks" with a fresh home photo: for each point click where it was really touched (the yellow ring is where vision aimed it), then Save. "New home photo" retakes it. If any touch met the page above the Z link height, that height goes into the book model (run stage 5 again).

7 · Touch demo not run

Book points only (no table touch). Each ticked point is touched lightly, back to back, at the book height the model has there (driven by the touches) plus the units above it (1 unit = 2 mm; 3 light-touched perfectly in the touch calibration). Corners are touched 15 mm in from the edge. Between points the arm goes up or down to half the home height, across, and straight down. If the load jumps before that height, the page is higher than thought: the arm backs off at once, the difference is reported, and that height goes into the model.

8 · Page flip

Midhat's hand-taught path (config/waypoints.yaml), moved with the book: every point is turned and shifted by how far the book has moved since the path was taught, and raised or lowered with its height. The book's place comes from the first capture + Z link. Press "The book is where the path works" once, with the book where the recorded path flips well; until then, and whenever the book hasn't moved, the recorded joints play exactly as taught.
Taught on 17 Oct, at 2x the teaching speed (~15 s): touch at the left page's outer edge, open the gripper to peel the top page up on the tape, swing it round the spine, pinch at 110°, carry to 160°, let go, home. Uses the first capture, the XY correction and the Z link book height. Settings: bookworm/gui/flip.py.
